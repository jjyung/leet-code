# 190. Reverse Bits

## Problem

<span style="color: #16a34a;"><strong>Easy</strong></span>

Reverse bits of a given 32 bits signed integer.

### Example 1

```text
Input: n = 43261596
Output: 964176192
Explanation:
Integer  Binary
43261596 00000010100101000001111010011100
964176192 00111001011110000010100101000000
```

### Example 2

```text
Input: n = 2147483644
Output: 1073741822
Explanation:
Integer      Binary
2147483644   01111111111111111111111111111100
1073741822   00111111111111111111111111111110
```

### Constraints

- `0 <= n <= 2^31 - 2`
- `n` is even.

Follow up: If this function is called many times, how would you optimize it?

## Answer

### 解題思路

這裡的 `reverse bits` 是把 bit 的排列順序倒過來。以 4 個 bit 為例，`0010` 反轉順序後是 `0100`；每個 bit 的數值不變，只是位置順序改變。

每輪依序做三件事：先保留 `n` 最右邊的最低位元；再將 `reversed` 左移一格，把剛取出的位元接到結果最右邊；最後讓 `n` 右移一格，消耗掉已取出的位元。用 4 個 bit 的 `0010` 示範，迴圈要跑 4 次：

以下二進位寫法由左至右是高位到低位；最右邊是最低位元（`bit 0`），所以 `0010` 第一個取出的位元是 `0`。

| 次數 | 當前輸入 `n` | 取出的最低位元 | 結果 `reversed` | 右移後的 `n` |
| --- | --- | --- | --- | --- |
| 開始 | `0010` | — | `0000` | — |
| 1 | `0010` | `0` | `0000` | `0001` |
| 2 | `0001` | `1` | `0001` | `0000` |
| 3 | `0000` | `0` | `0010` | `0000` |
| 4 | `0000` | `0` | `0100` | `0000` |

從 `n` 的讀取方向是由右往左；每讀出一個 bit，就送進 `reversed`，讓先前收集的 bit 向左挪一格。這不是把原本的 `0010` 一格一格循環左移。實際題目是 32 位元，因此程式固定重複 32 次。

Java 的 `int` 以 32 位元儲存。使用 `>>>` 將輸入無符號右移，確保最高位補 `0`；結果左移時即使超出有號整數的正數範圍，保留的 32 位元仍是題目所需的位元模式。

```java
class Solution {
    public int reverseBits(int n) {
        int reversed = 0;

        // 固定處理全部 32 個位元，包含前導零。
        for (int bit = 0; bit < 32; bit++) {
            // 將已收集的結果左移一位，並接上 n 目前最右邊的最低位元。
            reversed = (reversed << 1) | (n & 1);
            // n 無符號右移一位，消耗掉剛取出的最低位元。
            n >>>= 1;
        }

        return reversed;
    }
}
```

### 複雜度

- 時間複雜度：`O(w)`，`w` 是整數位元寬度；本題固定為 32，因此為 `O(1)`。
- 空間複雜度：`O(1)`，只使用固定數量的整數變數。

### 邊界條件

- 固定處理 32 位元，因此前導零也會被反轉到結果的高位。
- `n` 為偶數只代表最低位元是 `0`，迴圈仍須處理完整的 32 位元。
