## Problem

Given the head of a linked list, return the list after sorting it in ascending order.

### Example 1

```text
Input: head = [4,2,1,3]
Output: [1,2,3,4]
Explanation: The linked list is sorted in ascending order.
```

### Example 2

```text
Input: head = [-1,5,3,4,0]
Output: [-1,0,3,4,5]
Explanation: The linked list is sorted in ascending order.
```

### Example 3

```text
Input: head = []
Output: []
Explanation: The input linked list is empty, so the output is also empty.
```

### Constraints

The number of nodes in the list is in the range [0, 5 * 104].
-105 <= Node.val <= 105

### Follow-up

Follow up: Can you sort the linked list in O(n logn) time and O(1) memory (i.e. constant space)?

## Answer

### 解題思路

#### Merge Sort 的核心概念

Merge sort 的核心是「分割、排序、合併」：

1. 將資料分成較小的區段。
2. 讓每個小區段各自成為已排序的區段。
3. 合併兩個已排序的區段。因為兩邊都已排序，只要比較兩個區段目前最前面的節點，就能決定下一個應該放入結果的節點。

對 linked list 來說，merge sort 特別合適。陣列需要搬移元素才能合併，但 linked list 只要修改 `next` 指標即可重新排列節點，不需要隨機存取，也不需要建立暫存陣列。

#### 為什麼使用 bottom-up

常見的 top-down merge sort 會從中間把串列切成左右兩半，再遞迴排序左右兩邊。這種寫法直觀，但遞迴深度約為 `O(log n)`，因此會使用遞迴呼叫堆疊。

本題 follow-up 要求 `O(1)` memory，所以改用 bottom-up merge sort。它不遞迴切半，而是從最小的已排序區段開始，逐輪合併相鄰區段；所有操作都透過幾個指標完成，因此額外空間可以維持 `O(1)`。

#### `size` 為什麼每輪乘以 2

一開始每個單獨節點都可以視為長度為 `1` 的已排序區段，這就是 `size = 1` 的原因。每輪會將兩個長度最多為 `size` 的相鄰區段合併，合併後就得到長度最多為 `2 * size` 的排序區段，因此整輪完成後才把 `size` 乘以 2。

例如輸入 `[4, 2, 1, 3]`：

| `size` | 合併前的排序區段 | 合併後 |
| --- | --- | --- |
| 1 | `[4] [2]`、`[1] [3]` | `[2,4]`、`[1,3]` |
| 2 | `[2,4] [1,3]` | `[1,2,3,4]` |

因此程式中的 `size <<= 1` 等同於 `size = size * 2`。它不是把節點值乘以 2，也不是每處理一對節點就加倍；它是在整條串列完成一輪合併後，表示「目前已排序區段的長度增加一倍」。

#### 每輪如何處理串列

這裡不是把整條串列切成「左半邊」和「右半邊」。每次 `while` 都從 `current` 開始，依序取得三個部分：**第一段 `left`、第二段 `right`，以及第二段後方尚未處理的剩餘串列 `current`**。`left` 和 `right` 只是本次要合併的兩個區段名稱，不代表整條串列的左右兩半。

```text
current
    ├── 第一段 left  （最多 size 個節點）
    ├── 第二段 right （最多 size 個節點）
    └── 剩餘串列 current（留給下一次 while）
```

程式的兩次 `split` 正好負責切出這三個部分：

1. `ListNode left = current` 先把目前位置當成第一段的起點。
2. `split(left, size)` 切出第一段 `left`，並回傳第二段的起點，存入 `right`。
3. `split(right, size)` 再從第二段的起點切出最多 `size` 個節點，形成第二段 `right`；它的回傳值就是剩餘串列的起點，存入 `current`。
4. 如果節點數不足，`right` 可以是 `null`，或剩餘串列可以比 `size` 短；`mergeRuns` 都能直接處理。
5. `mergeRuns` 比較 `left` 與 `right` 的目前節點，將較小者接到 `previous` 後方；其中一段用完後，再把另一段剩餘節點整段接上。
6. 合併完成後，`previous` 移到剛完成區段的尾端，讓下一組合併可以接在正確位置。

每一輪開始時的 invariant 是：串列由多個已排序、長度最多為 `size` 的區段組成。每次合併兩個相鄰區段後，會得到一個已排序、長度最多為 `2 * size` 的區段；整輪結束後，這個 invariant 仍然成立，只是區段大小加倍。

使用 `dummy` node 是為了統一處理合併結果的頭節點。第一組區段合併後，新的最小節點可能不是原本的 `head`；讓 `previous` 一開始指向 `dummy`，就不必另外判斷頭節點是否改變。

相較之下，quick sort 需要以 pivot 分割節點，最差情況可能達到 `O(n^2)`，而且通常仍需要遞迴堆疊。這題使用 merge sort，可以保證 `O(n log n)` 時間，也能自然利用 linked list 的指標重新連接特性。

#### 演算法步驟

本題使用 bottom-up merge sort，由小到大合併相鄰的已排序子串列。每次 `while` 都是「取出第一段、第二段、保留剩餘串列，再合併前兩段」：

1. 先計算鏈結串列長度 `n`，再令每個子串列的大小 `size` 依序為 `1、2、4、...`。
2. 從 `current` 切出第一段 `left`，再切出第二段 `right`；第二次 `split` 的回傳值保留為下一次 `while` 的 `current`。
3. 使用 `mergeRuns` 將 `left` 與 `right` 依節點值由小到大接回結果串列。合併完成後，`previous` 移到這個合併區段的尾端。
4. 下一次 `while` 從剛才保留的剩餘串列 `current` 繼續取出下一組第一段與第二段。
5. 當 `size` 大於或等於 `n` 時，所有節點已經在同一個排序區段內，回傳 dummy node 後方的串列。

dummy node 可以統一處理第一個合併區段，避免另外判斷新的頭節點。這個做法只重新連接原有節點，不需要建立陣列或遞迴呼叫堆疊，因此符合題目要求的常數額外空間。

```java
class Solution {
    public ListNode sortList(ListNode head) {
        if (head == null || head.next == null) {
            return head;
        }

        int length = 0;
        for (ListNode current = head; current != null; current = current.next) {
            length++;
        }

        ListNode dummy = new ListNode(0);
        dummy.next = head;

        // 每輪將相鄰且已排序的區段合併，區段大小依序加倍。
        for (int size = 1; size < length; size <<= 1) {
            ListNode previous = dummy;
            ListNode current = dummy.next;

            while (current != null) {
                // 每次依序取出第一段 left、第二段 right，以及留給下一輪的剩餘串列 current。
                ListNode left = current;
                ListNode right = split(left, size);
                current = split(right, size);

                // 將這兩個候選區段依值排序後接到結果尾端。
                previous = mergeRuns(previous, left, right);
            }
        }

        return dummy.next;
    }

    private ListNode split(ListNode head, int size) {
        if (head == null) {
            return null;
        }

        ListNode current = head;
        for (int count = 1; count < size && current.next != null; count++) {
            current = current.next;
        }

        // 先保存下一個區段的起點，斷線後才能繼續處理剩餘節點。
        ListNode next = current.next;
        // 切斷目前區段，讓它成為獨立的排序串列；這不是刪除節點。
        current.next = null;
        return next;
    }

    private ListNode mergeRuns(ListNode previous, ListNode left, ListNode right) {
        // previous 是前一個合併區段的尾端，新的節點會接在它後面。
        ListNode tail = previous;

        // left 與 right 各自已排序；比較兩段目前的第一個節點即可決定下一個最小值。
        while (left != null && right != null) {
            if (left.val <= right.val) {
                tail.next = left;
                left = left.next;
            } else {
                tail.next = right;
                right = right.next;
            }
            // tail 永遠指向目前合併結果的最後一個節點。
            tail = tail.next;
        }

        // 其中一段用完後，另一段剩餘節點已經排序，整段直接接上即可。
        tail.next = left != null ? left : right;

        // tail 目前可能只在原本合併部分的尾端；向後走到整段結果的真正尾端，
        // 讓外層迴圈可以從這裡接上下一組 left 與 right。
        while (tail.next != null) {
            tail = tail.next;
        }

        return tail;
    }
}
```

### 說明

- `head == null` 時直接回傳空串列；只有一個節點時已經排序完成，也可直接回傳。
- `split` 會在剩餘節點不足 `size` 時自然提早停止，因此最後一段較短或沒有右半段時仍能正確合併。
- `left.val <= right.val` 會優先保留左半段的相同值，雖然本題不要求穩定排序，但不會影響結果。
- `n` 代表鏈結串列中的節點數量。每輪合併的總成本是 `O(n)`，共有 `O(log n)` 輪，因此時間複雜度為 `O(n log n)`。
- 除了少量指標與 dummy node 外，演算法不使用與 `n` 成正比的額外資料結構，空間複雜度為 `O(1)`。
