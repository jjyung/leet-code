# 399. Evaluate Division

<span style="color: #f59e0b;"><strong>Medium</strong></span>

## Problem

You are given an array of variable pairs equations and an array of real numbers values, where equations[i] = [Ai, Bi] and values[i] represent the equation Ai / Bi = values[i]. Each Ai or Bi is a string that represents a single variable.

You are also given some queries, where queries[j] = [Cj, Dj] represents the jth query where you must find the answer for Cj / Dj = ?.

Return the answers to all queries. If a single answer cannot be determined, return -1.0.

Note: The input is always valid. You may assume that evaluating the queries will not result in division by zero and that there is no contradiction.

Note: The variables that do not occur in the list of equations are undefined, so the answer cannot be determined for them.

### Example 1

```text
Input: equations = [["a","b"],["b","c"]], values = [2.0,3.0], queries = [["a","c"],["b","a"],["a","e"],["a","a"],["x","x"]]
Output: [6.00000,0.50000,-1.00000,1.00000,-1.00000]
Explanation:
Given: a / b = 2.0, b / c = 3.0
queries are: a / c = ?, b / a = ?, a / e = ?, a / a = ?, x / x = ?
return: [6.0, 0.5, -1.0, 1.0, -1.0 ]
note: x is undefined => -1.0
```

### Example 2

```text
Input: equations = [["a","b"],["b","c"],["bc","cd"]], values = [1.5,2.5,5.0], queries = [["a","c"],["c","b"],["bc","cd"],["cd","bc"]]
Output: [3.75000,0.40000,5.00000,0.20000]
```

### Example 3

```text
Input: equations = [["a","b"]], values = [0.5], queries = [["a","b"],["b","a"],["a","c"],["x","y"]]
Output: [0.50000,2.00000,-1.00000,-1.00000]
```

### Example 4

```text
Input: equations = [["x","y"],["y","z"],["p","q"]], values = [4.0,0.5,3.0], queries = [["x","z"],["z","x"],["x","q"],["p","q"],["y","z"]]
Output: [2.00000,0.50000,-1.00000,3.00000,0.50000]
Explanation:
Since x / z = (x / y) * (y / z) = 4.0 * 0.5 = 2.0, z / x = 0.5. x and q are in disconnected components, so their ratio cannot be determined.
```

### Example 5

```text
Input: equations = [["a","b"],["b","c"],["c","d"]], values = [2.0,3.0,4.0], queries = [["a","d"],["d","a"],["c","a"],["d","c"]]
Output: [24.00000,0.04167,0.16667,0.25000]
Explanation:
a / d = (a / b) * (b / c) * (c / d) = 2.0 * 3.0 * 4.0 = 24.0. Reverse queries use the reciprocal of the corresponding ratio.
```

equations[i].length == 2

values.length == equations.length
0.0 < values[i] <= 20.0
1 <= queries.length <= 20
queries[i].length == 2
1 <= Cj.length, Dj.length <= 5
Ai, Bi, Cj, Dj consist of lower case English letters and digits.

## Answer

### 解題思路

#### 為什麼這題可以用圖？

把每個變數當成圖中的一個**節點**。已知兩個變數的除法結果，就代表它們之間有一條帶有比值的**邊**。例如 `a / b = 2.0`，建立 `a → b`、權重 `2.0` 的邊；反向也能推得 `b / a = 1 / 2.0`，所以再建立 `b → a`、權重 `0.5` 的邊。

圖上的路徑代表可以串接的一連串等式。若 `a / b = 2.0` 且 `b / c = 3.0`，中間的 `b` 可以約掉，因此 `a / c = (a / b) × (b / c) = 6.0`。所以沿路徑走訪時，把每條邊的權重相乘，就能算出起點除以終點的結果。若兩個變數之間沒有路徑，表示現有等式無法推得答案。

#### 用 Example 1 走一次

題目給定 `a / b = 2.0`、`b / c = 3.0`，建立的正向邊與反向邊如下：

```text
a --2.0--> b --3.0--> c
a <--0.5-- b <--0.333...-- c
```

查詢 `a / c` 時，從 `a` 開始逐層探索：

1. 從 `a` 沿權重 `2.0` 的邊到 `b`，目前乘積是 `1.0 × 2.0 = 2.0`。
2. 從 `b` 沿權重 `3.0` 的邊到 `c`，目前乘積是 `2.0 × 3.0 = 6.0`。
3. 抵達目標 `c`，因此答案是 `6.0`。

反向查詢 `c / a` 則沿反向邊走：`c → b → a`，乘積為 `(1 / 3.0) × (1 / 2.0) = 1 / 6.0`。查詢 `a / a` 時，因為 `a` 是圖中已知的節點，答案為 `1.0`。查詢 `x / x` 時，雖然起點和終點相同，但 `x` 沒有出現在任何等式中，不是圖中的節點，因此答案仍是 `-1.0`。

程式對每筆查詢使用廣度優先搜尋（BFS）。佇列保存待探索的變數，`ratioFromStart` 同時記錄已走訪的變數，以及分子除以該變數的累積比值。若目前已知 `start / current`，沿著權重為 `current / next` 的邊前進後，就得到 `start / next = (start / current) × (current / next)`。找不到目標或任一變數不存在時回傳 `-1.0`；已知變數查詢自身時，起始累積值 `1.0` 就是答案。

```java
import java.util.*;

class Solution {
    public double[] calcEquation(List<List<String>> equations, double[] values,
                                List<List<String>> queries) {
        Map<String, Map<String, Double>> graph = new HashMap<>();

        // 建立加權有向圖；反向邊的權重是原比值的倒數。
        for (int i = 0; i < equations.size(); i++) {
            List<String> equation = equations.get(i);
            // equation[0] 是分子，equation[1] 是分母。
            String numerator = equation.get(0);
            String denominator = equation.get(1);
            // values[i] 表示 numerator / denominator 的比值。
            double numeratorOverDenominator = values[i];

            // numerator → denominator 的權重是原比值。
            graph.computeIfAbsent(numerator, key -> new HashMap<>())
                 .put(denominator, numeratorOverDenominator);
            // denominator → numerator 的權重是原比值的倒數。
            graph.computeIfAbsent(denominator, key -> new HashMap<>())
                 .put(numerator, 1.0 / numeratorOverDenominator);
        }

        double[] answers = new double[queries.size()];
        for (int i = 0; i < queries.size(); i++) {
            List<String> query = queries.get(i);
            answers[i] = calculateRatio(query.get(0), query.get(1), graph);
        }
        return answers;
    }

    private double calculateRatio(String start, String target,
                                  Map<String, Map<String, Double>> graph) {
        // 未出現在任何方程式中的變數沒有對應節點。
        if (!graph.containsKey(start) || !graph.containsKey(target)) {
            return -1.0;
        }

        Queue<String> queue = new ArrayDeque<>();
        Map<String, Double> ratioFromStart = new HashMap<>();
        queue.offer(start);
        ratioFromStart.put(start, 1.0);

        while (!queue.isEmpty()) {
            String current = queue.poll();
            double startOverCurrent = ratioFromStart.get(current);

            // 抵達分母節點時，累積值就是 start / target。
            if (current.equals(target)) {
                return startOverCurrent;
            }

            for (Map.Entry<String, Double> edge : graph.get(current).entrySet()) {
                String next = edge.getKey();
                if (ratioFromStart.containsKey(next)) {
                    continue;
                }

                // start / next = (start / current) * (current / next)。
                ratioFromStart.put(next, startOverCurrent * edge.getValue());
                queue.offer(next);
            }
        }

        return -1.0;
    }
}
```

### 複雜度

- 時間複雜度：建圖為 `O(E)`；每筆查詢最壞走訪整張圖，總計為 `O(Q(V + E))`。其中 `V` 是不同變數的數量、`E` 是方程式數量，`Q` 是查詢數量。
- 空間複雜度：建圖使用 `O(V + E)`；單次 BFS 的佇列與比值表最多使用 `O(V)`，因此總額外空間為 `O(V + E)`。
