# 300. Longest Increasing Subsequence

## Problem

<span style="color: #f59e0b;"><strong>Medium</strong></span>

Given an integer array nums, return the length of the longest strictly increasing subsequence.

### Example 1

```text
Input: nums = [10,9,2,5,3,7,101,18]
Output: 4
Explanation: The longest increasing subsequence is [2,3,7,101], therefore the length is 4.
```

### Example 2

```text
Input: nums = [0,1,0,3,2,3]
Output: 4
Explanation: One longest increasing subsequence is [0,1,2,3].
```

### Example 3

```text
Input: nums = [7,7,7,7,7,7,7]
Output: 1
Explanation: Any single 7 forms a longest increasing subsequence.
```

Constraints:

- 1 <= nums.length <= 2500
- -10^4 <= nums[i] <= 10^4

Follow up: Can you come up with an algorithm that runs in O(n log(n)) time complexity?

## Answer

### 解題思路

使用 `tails` 記錄目前處理過的數字中，各種長度的遞增子序列能達到的最小結尾值。`tails[i]` 是長度為 `i + 1` 的遞增子序列的最小結尾；這些結尾值嚴格遞增，因此可以用二分搜尋。

對每個數字，找到 `tails` 中第一個大於或等於它的位置並替換。較小的結尾更容易接上後續數字，且不會改變該子序列的長度；若找不到這個位置，代表數字比所有結尾都大，可以延長最長子序列。遇到相同數字時替換而不延長，才能符合嚴格遞增的要求。

`tails` 的內容不一定是同一條實際子序列，但每個位置都代表對應長度可達成的最小結尾，因此最後有效的元素數量就是答案。

例如依序處理 `[1, 4, 2, 3]`：

| 目前數字 | 更新後的 `tails` | `size` | 原因 |
| --- | --- | --- | --- |
| 1 | `[1]` | 1 | 建立長度為 1 的子序列。 |
| 4 | `[1, 4]` | 2 | `4` 比所有結尾都大，可以延長。 |
| 2 | `[1, 2]` | 2 | 用較小的 `2` 取代 `4`，讓長度為 2 的子序列更容易接上後面的數字。 |
| 3 | `[1, 2, 3]` | 3 | `3` 可以接在結尾為 `2` 的子序列後面。 |

#### 二分搜尋的範圍

`size` 是 `tails` 的有效元素數量，也是目前找到的最長遞增子序列長度。搜尋從 `left = 0`、`right = size` 開始，尚待檢查的範圍是 `[left, right)`：包含 `left`，但不包含 `right`。

- 若 `tails[mid] < num`，由於結尾值遞增，`mid` 及其左側都太小，將 `left` 設為 `mid + 1`。
- 若 `tails[mid] >= num`，`mid` 可能是答案，但左側也可能有更早的位置。將 `right` 設為 `mid`，繼續檢查左側；`mid` 雖不再位於待檢查範圍，仍作為答案的邊界候選保留。

當 `left == right` 時，兩者所在位置就是第一個大於或等於 `num` 的位置。若所有有效結尾都小於 `num`，該位置會等於 `size`，代表可以在末尾新增並將 `size` 加一。

#### 如何判斷搜尋結束後使用哪個指標

這段程式使用 `while (left < right)`，每次更新都會縮小範圍，而且不會讓 `left` 超過 `right`；因此離開迴圈時，兩者必定相等。此時寫 `tails[left] = num` 或 `tails[right] = num` 結果相同。這裡慣用 `left` 表示找到的位置，並在後續 `left == size` 的判斷中保持一致，方便閱讀；這不是由左到右搜尋的要求。

遇到其他二分搜尋寫法時，先確認搜尋範圍是否包含兩端、迴圈何時結束，以及結束後指標各代表什麼，再決定使用哪個指標。例如使用 `while (left <= right)` 的寫法，結束時通常是 `left > right`，不能直接假設兩者相等。

```java
class Solution {
    public int lengthOfLIS(int[] nums) {
        int[] tails = new int[nums.length];
        // 有效結尾值的數量，也就是目前最長遞增子序列的長度。
        int size = 0;

        for (int num : nums) {
            // 在 [left, right) 中搜尋第一個大於或等於 num 的結尾。
            int left = 0;
            int right = size;
            while (left < right) {
                int mid = left + (right - left) / 2;
                if (tails[mid] < num) {
                    // mid 及其左側都太小，可以排除。
                    left = mid + 1;
                } else {
                    // mid 可能是答案，保留為邊界並繼續搜尋左側。
                    right = mid;
                }
            }

            // 較小的結尾更容易接上後續數字；相等時不延長長度。
            tails[left] = num;
            // 找不到較大或相等的結尾時，在末尾新增並增加長度。
            if (left == size) {
                size++;
            }
        }

        return size;
    }
}
```

### 複雜度與邊界條件

令 `n` 為 `nums` 的長度。每個元素最多進行一次二分搜尋，時間複雜度為 **O(n log n)**；`tails` 最多儲存 `n` 個元素，空間複雜度為 **O(n)**。

單一元素的結果為 1；重複元素不會延長子序列。負數可依相同的大小比較處理；雖然題目保證陣列非空，此實作對空陣列也會回傳 0。
