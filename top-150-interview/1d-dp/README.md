## 解題思路提示

看到「走到第 `i` 步的方式數」、「前 `i` 個元素的最佳答案」或「每個位置只能從前面幾個位置轉移」時，先考慮一維 DP：

1. 定義 `dp[i]` 的確切語意，不要只寫成「目前答案」。
2. 找出最後一步可能來自哪些狀態，寫出轉移式。
3. 設定最小且足夠的 base case，再依序由左到右計算。
4. 若 `dp[i]` 只依賴最近幾個狀態，可壓縮成數個變數。

## DP 初始化記憶法

先問自己：「這個位置的 `0` 是合法答案，還是代表目前不知道／無法到達？」初始化值要配合狀態的意義與轉移運算選擇：

| 目的 | 不可達狀態 | 記憶方式 |
| --- | --- | --- |
| 尋找最小值 | 正無限大，例如 `amount + 1` | `min(有效值, 正無限大)` 會保留有效值 |
| 尋找最大值 | 負無限大，或小於所有合法答案的數字 | `max(有效值, 負無限大)` 會保留有效值 |
| 計算方法數 | `0` | `0` 代表目前有 0 種方法；`dp[0]` 常是 `1` |
| 判斷是否可達 | `false` | 另外用布林值表示狀態是否已到達 |

### 何時可以使用 `0` 或負值

- `0` 可以是合法的 base case，例如 Coin Change 的 `dp[0] = 0`，代表湊出 0 元需要 0 枚硬幣。
- 若「什麼都不選」本身是合法選擇，且所有合法答案都是非負數，整個 `dp` 陣列才可能直接填 `0`。
- `-1` 可以表示「不可達」，但必須先排除它，不能直接讓它參與 `min` 或加法；而且合法答案不能是 `-1` 或更小。
- 若合法答案可能為負數，就不能隨便使用 `0` 或 `-1`；應使用足夠小的初始值，或另外使用 `reachable` 陣列表示可達性。

Coin Change 是尋找最少硬幣數量，因此使用：

```text
dp[0] = 0
其他 dp[i] = amount + 1
```

`amount + 1` 大於任何可行答案，代表「目前無法湊出」。不要直接使用 Java `int[]` 的預設值 `0`，否則 `min(0, 新答案)` 會錯誤地把每個金額都當成只需要 0 枚硬幣。若使用 `Integer.MAX_VALUE`，在加上 `1` 前必須先判斷是否為不可達，避免整數溢位。

## 必要資料結構與演算法

- **狀態陣列**：保存每個前綴或位置的最佳值、可行性或方法數。
- **滾動變數**：當轉移只依賴 `i - 1`、`i - 2` 時，將空間從 $O(n)$ 降為 $O(1)$。
- **選擇型 DP**：像 House Robber 一類題目，常比較「選目前元素」與「跳過目前元素」兩種方案。
- **複雜度**：通常每個狀態只計算一次，時間為 $O(n)$；`n` 是輸入長度或步數。

## 複習提醒

- 先寫出暴力遞迴的「最後一步」，再將重複子問題改成 DP。
- 分清楚「方法數」要相加、「最佳值」通常取 `max` 或 `min`。
- 檢查 `n = 0`、`n = 1`、只有一個可選元素，以及答案可能溢位的情況。
- 做空間最佳化後，確認更新順序不會覆蓋下一個仍需要的舊狀態。
