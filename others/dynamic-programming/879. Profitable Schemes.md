# 879. Profitable Schemes

<span style="color: #dc2626;"><strong>Hard</strong></span>

## Problem

There is a group of `n` members, and a list of various crimes they could commit. The `i`th crime generates a `profit[i]` and requires `group[i]` members to participate in it. If a member participates in one crime, that member can't participate in another crime.

Let's call a profitable scheme any subset of these crimes that generates at least `minProfit` profit, and the total number of members participating in that subset of crimes is at most `n`.

Return the number of schemes that can be chosen. Since the answer may be very large, return it modulo `10^9 + 7`.

### Example 1

```text
Input: n = 5, minProfit = 3, group = [2,2], profit = [2,3]
Output: 2
Explanation: To make a profit of at least 3, the group could either commit crimes 0 and 1, or just crime 1.
In total, there are 2 schemes.
```

### Example 2

```text
Input: n = 10, minProfit = 5, group = [2,3,5], profit = [6,7,8]
Output: 7
Explanation: To make a profit of at least 5, the group could commit any crimes, as long as they commit one.
There are 7 possible schemes: (0), (1), (2), (0,1), (0,2), (1,2), and (0,1,2).
```

### Constraints

- `1 <= n <= 100`
- `0 <= minProfit <= 100`
- `1 <= group.length <= 100`
- `1 <= group[i] <= 100`
- `profit.length == group.length`
- `0 <= profit[i] <= 100`

## Answer

### 解題思路

這是一個「每個犯罪最多選一次」的 0/1 背包計數問題。由於只關心收益是否達到 `minProfit`，超過門檻的收益可以全部視為 `minProfit`，以控制狀態數量。

定義 `dp[member][currentProfit]` 表示處理過目前犯罪後，**恰好使用 `member` 位成員**，且收益（超過門檻時封頂為 `minProfit`）為 `currentProfit` 的方案數。

初始時不選任何犯罪，因此 `dp[0][0] = 1`，其餘狀態為 `0`。處理一項犯罪時，可以選擇它，轉移方式如下：

```text
nextProfit = min(minProfit, currentProfit + profit[i])
dp[member][nextProfit] += dp[member - group[i]][currentProfit]
```

成員數必須由 `n` 遞減至 `group[i]`，確保同一項犯罪不會在同一輪被重複使用。最後將 `dp[member][minProfit]`（`member` 從 `0` 到 `n`）全部加總，即為使用不超過 `n` 位成員且收益達標的方案數。

```java
class Solution {
    private static final int MOD = 1_000_000_007;

    public int profitableSchemes(int n, int minProfit, int[] group, int[] profit) {
        // dp[member][currentProfit]：已處理前面犯罪後，恰好使用 member 位成員，
        // 且收益（超過 minProfit 時封頂）為 currentProfit 的方案數。
        int[][] dp = new int[n + 1][minProfit + 1];

        // 不選任何犯罪時，使用 0 位成員且收益為 0，是唯一一種方案。
        dp[0][0] = 1;

        for (int crime = 0; crime < group.length; crime++) {
            // 目前犯罪需要的成員數與能產生的收益。
            int requiredMembers = group[crime];
            int crimeProfit = profit[crime];

            // 反向枚舉成員數，確保同一項犯罪不會在本輪被重複選取。
            for (int member = n; member >= requiredMembers; member--) {
                // 反向枚舉收益，配合 0/1 背包的反向更新方式。
                for (int currentProfit = minProfit; currentProfit >= 0; currentProfit--) {
                    // 收益達到門檻後不必再區分實際數值，因此封頂為 minProfit。
                    int nextProfit = Math.min(minProfit, currentProfit + crimeProfit);

                    // 保留原本的方案，並加入「選擇目前犯罪」所形成的新方案。
                    // 來源狀態：少使用 requiredMembers 位成員，且尚未加入 crimeProfit。
                    dp[member][nextProfit] = (int) ((dp[member][nextProfit]
                            + (long) dp[member - requiredMembers][currentProfit]) % MOD);
                }
            }
        }

        int answer = 0;
        // dp 使用的是「恰好」member 位成員，因此要加總所有不超過 n 位的達標方案。
        for (int member = 0; member <= n; member++) {
            // 只統計收益已達到 minProfit 的狀態。
            answer += dp[member][minProfit];
            if (answer >= MOD) {
                // 控制總和在模數範圍內，避免整數溢位。
                answer -= MOD;
            }
        }

        return answer;
    }
}
```

### 複雜度分析

- 時間複雜度：`O(k * n * minProfit)`，其中 `k` 是犯罪數量。
- 空間複雜度：`O(n * minProfit)`。
